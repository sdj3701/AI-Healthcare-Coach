# 전면 카메라 관절 추적 안정화 계획

작성일: 2026-07-23
상태: **1차 구현 반영 — 실기기 튜닝 대기**
대상: iPhone 전면 카메라, `MediaPipePoseTrackingProvider`, `JointTrackingController`, `PoseLandmarkStabilizer`, `RealtimeFeedbackOrchestrator`

## 1. 목적

전면 카메라로 스쿼트를 촬영할 때 관절이 흔들리거나 잠시 사라지고, 그 흔들림이 자세 오류·반복 수·골반 판정으로 이어지는 문제를 줄인다. 목표는 관절을 무조건 강하게 고정하는 것이 아니라 다음 세 조건을 함께 만족하는 것이다.

1. 화면의 관절 오버레이가 자연스럽고 안정적으로 따라온다.
2. 빠르게 내려가거나 올라갈 때 실제 동작이 과도하게 늦어지지 않는다.
3. 관절 신뢰도가 낮은 구간은 잘못된 자세 피드백 대신 `분석 보류`로 처리한다.

이 계획은 기존 [CameraPoseTrackingOptimizationPlan.md](CameraPoseTrackingOptimizationPlan.md)의 성능·비동기 처리 계획과 [CameraPoseLifecycleRecoveryPlan.md](CameraPoseLifecycleRecoveryPlan.md)의 카메라 재시작/좌표 계약을 보완한다. 카메라 수명주기나 좌우 미러링 계약을 다시 바꾸는 계획은 아니다.

## 2. 현재 구현과 확인된 한계

현재 실제 분석 경로는 다음과 같다.

```text
전면 WebCamTexture
  -> MediaPipe Pose 33개 landmark
  -> PoseLandmarkStabilizer
       (3-샘플 중앙값 + 고정 EMA + 절대 좌표 jump 제거 + 저신뢰 hold)
  -> PoseFrameNormalizer
  -> PoseFeatureExtractor / PhaseDetector / RuleEngine
```

이미 적용된 안정화 장치:

- 최근 3개 landmark의 중앙값으로 단발성 튐을 줄인다.
- EMA로 landmark를 부드럽게 만든다.
- 화면 정규화 좌표에서 큰 jump는 최대 3프레임까지 이전 좌표를 유지한다.
- 낮은 visibility/confidence는 최대 0.35초 동안 마지막 유효 좌표를 사용한다.
- 실시간 규칙은 최근 시간 창의 위반 비율을 사용하며, 핵심 관절이 부족하면 자세 오류보다 visibility 안내를 우선한다.
- iOS에서는 single-flight 추론과 최신 프레임 우선 방식을 사용해 결과 대기열을 만들지 않는다.

하지만 전면 카메라 환경에서는 다음 한계가 남는다.

| 한계 | 흔들림/오판으로 이어지는 이유 |
| --- | --- |
| 고정 EMA 계수 | 서 있는 동안에는 충분히 부드럽지 않고, 하강·상승 중에는 실제 움직임보다 늦게 따라갈 수 있다. |
| 모든 관절에 같은 jump 임계값 | 얼굴·손목처럼 빠른 관절과 hip·knee·ankle처럼 자세 판정에 중요한 관절의 특성이 다르다. |
| 화면 절대 거리 기준 | 사용자가 카메라에 가까워지거나 멀어지면 동일한 실제 움직임도 다른 크기의 jump로 보인다. |
| 저신뢰 hold | 짧은 가림에는 유용하지만, 오래 지속되면 이전 자세를 현재 자세처럼 보이게 할 수 있다. |
| 품질과 규칙의 결합이 약함 | landmark가 일부 불안정해도 phase/반복 판정이 계속 진행될 여지가 있다. |
| 전면 카메라 입력 조건 | 광각 왜곡, 낮은 조도, 흔들리는 손, 화면 가장자리, 하체 가림, 빠른 동작에서 landmark 품질이 급격히 낮아진다. |

## 3. 전면 카메라에서 특히 흔들리는 원인

### 3.1 촬영 조건

- 사용자가 화면에 너무 가까우면 발목·발끝이 잘리고, 너무 멀면 hip/knee가 몇 픽셀 수준으로 작아진다.
- 전면 카메라는 광각 특성이 있어 화면 가장자리에서 신체 비율과 landmark 위치가 더 흔들릴 수 있다.
- 어두운 실내, 역광, 운동복과 배경의 낮은 대비, 모션 블러는 visibility를 낮춘다.
- 휴대폰을 손으로 들면 카메라 자체가 움직인다. 이 경우 사용자의 관절 변화와 카메라 변화가 2D landmark에서 섞인다.

### 3.2 모델과 2D 관측의 한계

- MediaPipe landmark는 카메라 영상에서 추정한 값이므로 실제 관절의 의료용 측정값이 아니다.
- 몸을 비스듬히 돌리거나 한쪽 다리가 가려지면 좌우 hip/knee의 화면상 위치가 실제 자세와 다르게 투영된다.
- 전면 카메라의 셀피 미러는 표시 문제와 분석 문제를 구분해야 한다. 현재 계약은 분석 좌표를 upright 상태로 유지하고, 셀피 미러는 preview에만 적용한다.

### 3.3 처리 지연

- `GetPixels32`, 네이티브 추론, JSON 경계, UI/TTS가 한 번에 겹치면 결과 간격이 일정하지 않을 수 있다.
- 평균 FPS가 충분해도 p95 지연이 크면 landmark 사이의 시간 간격이 늘어, EMA와 속도 기반 phase 판정이 불안정해진다.

## 4. 개선 원칙

1. **추적 품질과 자세 품질을 분리한다.** 관절이 불안정한 구간은 “자세가 나쁨”이 아니라 “판정 보류”로 처리한다.
2. **고정 평활화보다 적응형 평활화를 쓴다.** 천천히 움직일 때는 강하게 부드럽게, 빠르게 움직일 때는 빠르게 따라간다.
3. **사람 크기 기준으로 이상치를 판정한다.** 화면 절대 픽셀/정규화 거리보다 현재 torso/hip 폭에 비례한 임계값을 사용한다.
4. **전면 카메라의 정면 품질을 확인한다.** 좌우 hip·shoulder 폭, 핵심 관절 confidence, 전신 포함 여부가 부족하면 골반/좌우 대칭 같은 정면 전제 규칙을 중단한다.
5. **성능 예산을 넘기지 않는다.** 결과 큐를 만들지 않고, 품질이 나쁜 상황에서 해상도·FPS를 무조건 올리지 않는다.
6. **사용자에게 원인을 알려 준다.** 오류 피드백 전에 “한 걸음 뒤로”, “발끝까지 보이게”, “휴대폰을 고정” 같은 촬영 안내를 제공한다.

## 5. 승인 후 구현할 단계

### 단계 0 — 실측과 진단 로그 추가

목적: 흔들림이 모델 입력 문제인지, landmark 후처리 문제인지, 추론 지연 문제인지 구분한다.

추가할 최소 지표:

- 매 결과의 핵심 관절 최소 confidence와 valid core 여부
- hip/shoulder 폭, 전신 포함 여부, 마지막 유효 frame 경과 시간
- raw landmark와 stabilized landmark 사이 거리의 요약값
- readback / native submit / result poll / 전체 inference의 p50·p95·max
- dropped frame, no-pose, low-confidence, outlier hold 횟수

개인정보 원칙:

- 원본 영상은 저장하지 않는다.
- landmark 전체 로그는 기존 QA 옵션을 켠 경우에만 짧게 보관한다.
- 기본 사용자 세션에는 품질 요약과 피드백 이벤트만 남긴다.

완료 조건: “흔들림” 사례마다 입력 품질 저하, 추론 지연, smoothing lag 중 어느 쪽인지 로그로 구분할 수 있다.

### 단계 1 — 추적 품질 게이트와 화면 안내

새 내부 상태를 `Good`, `Degraded`, `Unavailable` 세 단계로 만든다.

| 상태 | 조건 예시 | 앱 동작 |
| --- | --- | --- |
| Good | 양 hip/knee/ankle와 shoulders가 충분히 보이고 최근 프레임 간격이 정상 | 오버레이, phase, 반복, 자세 규칙 모두 실행 |
| Degraded | 일부 핵심 관절 confidence가 낮거나 신체 폭/전신 포함이 경계값 근처 | 오버레이는 마지막 안정 좌표를 짧게 유지, 자세 Warning과 rep 확정은 보류 |
| Unavailable | 핵심 관절 부족이 지속되거나 결과가 오래됨 | overlay를 흐리게/숨기고 촬영 안내만 표시 |

중요한 정책:

- Degraded/Unavailable에서 **새로운 자세 오류 Warning은 생성하지 않는다.**
- `CorrectRepCount`도 충분한 Good evidence가 없는 반복을 성공으로 세지 않는다.
- 품질 상태는 최소 유지 시간(hysteresis)을 둬 한 프레임마다 Good/Degraded가 깜빡이지 않게 한다.

권장 사용자 안내 우선순위:

1. 발목·발끝 누락: `발끝까지 보이도록 휴대폰에서 한 걸음 뒤로 이동해 주세요.`
2. hip/shoulder 폭 부족 또는 큰 회전: `정면을 향해 서고 몸 전체가 화면 가운데에 오도록 맞춰 주세요.`
3. 지속적인 blur/jitter: `휴대폰을 고정하고 밝은 곳에서 다시 시도해 주세요.`

### 단계 2 — 핵심 관절용 적응형 안정화

대상 우선순위:

1. hip, knee, ankle: 반복·골반·중심·깊이 판정에 직접 사용
2. shoulder: 상체·골반 기준선에 사용
3. 발끝/heel: 정렬 및 전신 포함 안내
4. 손목/얼굴: 스쿼트 핵심 규칙에는 낮은 우선순위

추천 방식: 현재의 3-샘플 중앙값을 유지하고, 그 뒤 EMA 계수를 속도·confidence·frame 간격에 따라 조절한다.

```text
새 위치 = 이전 안정 위치 + alpha × (중앙값 위치 - 이전 안정 위치)

느리고 confidence 높은 경우: 작은 alpha  -> 더 부드럽게
빠른 동작 또는 큰 정상 이동: 큰 alpha     -> 지연 감소
confidence 저하/비정상 jump: 이전 위치를 매우 짧게 유지하거나 분석 보류
```

구현 시 제한:

- hold는 현재 0.35초보다 짧은 기본값(예: 0.20~0.25초)부터 실측한다. 오래된 좌표를 현재 자세로 쓰지 않는다.
- jump 기준은 torso 길이 또는 hip 폭을 기준으로 정규화한다. 사용자와 카메라의 거리가 달라도 판정 강도가 비슷해진다.
- 연속 outlier 이후에는 즉시 raw 좌표를 채택하지 않고, 재획득(reacquire) 2~3프레임을 거친 뒤 새 기준점을 만든다.
- z는 2D 화면 보정에는 직접 섞지 않는다. 단, 정면 여부/가림의 보조 신호로만 실험한다.

### 단계 3 — 정면 카메라 전용 규칙 보호

다음 규칙은 정면 관측 품질이 충분할 때만 실행한다.

- 골반 수평 (`squat_pelvic_tilt`)
- 좌우 무릎 대칭
- 좌우 무릎-발끝 정렬
- 좌우 체중 중심 비교

정면 품질 판단 예시:

- hip과 shoulder의 화면상 폭이 최소값 이상
- 좌우 핵심 관절 confidence가 모두 기준 이상
- hip 폭 대비 shoulder 폭 비율이 비정상적으로 작지 않음
- 최근 0.5초 동안 landmark 폭과 orientation이 급격히 바뀌지 않음

반대로 깊이·상체 기울기는 카메라 각도에 따라 의미가 달라질 수 있으므로, 정면/측면 어느 자세를 기본 촬영 자세로 지원할지 제품 정책을 명확히 해야 한다. 현 MVP의 좌우 비교 규칙과 골반 규칙은 **정면 전면 카메라 촬영**을 기본으로 한다.

### 단계 4 — 추론 속도와 품질의 균형

기본 전략은 “낮은 품질에서 FPS를 올려 해결하지 않는다”이다. blur나 가림은 30 FPS Pose로도 해결되지 않고 배터리·발열·메인 스레드 부담만 늘릴 수 있다.

권장 시작값:

| 조건 | 카메라 요청 | Pose 목표 | 동작 |
| --- | --- | --- | --- |
| 일반 iPhone / 밝은 실내 | 640×480, 20~30 FPS | 10~12 FPS | 기본 profile |
| p95 추론 지연 증가 또는 발열 | 640×480, 20 FPS | 8~10 FPS | smooth/quality gate 유지, 규칙 보수화 |
| 충분히 안정적인 고성능 기기 | 640×480, 30 FPS | 최대 15 FPS | 실측 통과 시에만 |

적응형 profile 전환은 즉시 왕복하지 않는다. p95·드롭·저신뢰 비율이 일정 시간 지속될 때만 12→10→8 FPS로 낮추고, 회복은 더 긴 안정 구간 뒤에 한 단계씩 진행한다. 카메라 재시작이 필요한 해상도 변경은 운동 중 자동 실행하지 않는다.

### 단계 5 — 분석 시작 전 짧은 캘리브레이션

Start 직후 1~2초 동안 사용자가 정면으로 편하게 서 있도록 안내하고, 다음을 측정한다.

- 실제 hip/shoulder 폭과 torso 길이의 중앙값
- 핵심 관절 confidence 기준선
- 카메라가 흔들리지 않는지 여부

이 값은 의학적 기준을 개인화하는 용도가 아니다. 화면상 크기와 정상 jitter 범위를 정해 **이상치 제거와 전신 가시성 판정을 사용자/거리마다 안정적으로 만들기 위한 기준**이다. 캘리브레이션 중에는 자세 오류나 반복 수를 판정하지 않는다.

## 6. 선택지와 장단점

| 선택지 | 장점 | 단점 | 권장 여부 |
| --- | --- | --- | --- |
| 고정 EMA 계수만 높이기 | 코드가 매우 간단하고 overlay 떨림이 빨리 줄어든다 | 실제 하강/상승이 늦게 따라와 깊이·phase가 오판될 수 있다 | 비권장 |
| Pose FPS를 20~30으로 올리기 | 빠른 기기에서는 temporal sample이 증가한다 | iPhone 발열, readback, GPU/CPU 부하가 증가하며 가림·blur는 해결하지 못한다 | 실측 통과 기기에서만 |
| 해상도를 높이기 | 멀리 선 사용자의 관절 픽셀이 늘 수 있다 | 메모리 대역폭·추론 시간이 증가해 버벅임이 더 심해질 수 있다 | 기본값으로 비권장 |
| 3-샘플 중앙값 + 적응형 EMA | 단발 튐을 줄이면서 빠른 동작 지연을 제한한다 | 파라미터 튜닝과 합성 테스트가 필요하다 | 권장 |
| confidence 기반 quality gate | 불안정한 landmark를 자세 오류로 말하지 않는다 | 일시적으로 코칭이 멈춘 것처럼 보일 수 있다 | 권장. 명확한 화면 안내 필수 |
| body-scale 정규화 jump 기준 | 거리 변화에도 outlier 판단이 일관된다 | 캘리브레이션/scale 계산이 추가된다 | 권장 |
| 휴대폰 고정 안내만 강화 | 구현 비용이 낮다 | 촬영 조건이 나쁜 사용자는 여전히 추적 실패한다 | quality gate와 함께 사용 |
| 더 무거운 Pose 모델로 교체 | 일부 난이도 높은 장면에서 정확도가 좋아질 수 있다 | 지연·발열·배터리·앱 크기 증가, 현재 문제의 원인이 입력/후처리라면 효과가 작다 | 마지막 단계에서 A/B 테스트 |

## 7. 검증 계획

### 기능 회귀

- `Start -> Stop -> Start` 10회와 전면/후면 전환 10회에서 추적이 재시작되는지 확인한다.
- 전면 preview와 overlay가 좌우·회전 상태에서 여전히 일치하는지 확인한다.
- 정면으로 서기, 천천히 스쿼트, 빠른 스쿼트에서 phase와 rep 수가 기존 기준보다 나빠지지 않는지 확인한다.
- 한쪽 다리/발목을 잠시 가린 뒤 재등장했을 때, 오래된 좌표가 0.25초 이상 남지 않고 안정적으로 재획득되는지 확인한다.

### 품질 시나리오

| 시나리오 | 기대 결과 |
| --- | --- |
| 밝은 실내, 정면, 전신 포함 | Good 유지, overlay jitter 감소, 자세·rep 판정 정상 |
| 휴대폰이 약간 기울어짐 | 골반/좌우 규칙은 camera roll만으로 Warning을 내지 않음 |
| 빠른 하강·상승 | 안정화 지연이 과도하지 않고 phase 순서 유지 |
| 발목 또는 한쪽 knee 가림 | Degraded/Unavailable 안내, 새 자세 Warning·정확 rep 확정 보류 |
| 화면 가장자리·몸 회전 | 정면 전제 규칙 보류, 잘못된 좌우/골반 피드백 없음 |
| 낮은 조도·motion blur | tracking quality 안내가 자세 오류보다 먼저 표시 |
| TTS on/off | p95, drop, low-confidence 비율 차이를 별도로 기록 |

### 성능 수락 기준 초안

- 실제 성공 Pose FPS: 기본 profile에서 평균 10 이상
- p95 inference: 설정 interval보다 지속적으로 길지 않을 것 (12 FPS라면 약 83ms를 참고)
- 새 GC 할당: 안정화 hot path에서 프레임별 컬렉션/배열 생성 없음
- 드롭: 초당 1 이하를 목표로 하되, 품질 문제가 입력 가림인지 처리 용량인지 분리해 기록
- 품질 상태: 정상 촬영에서 Good 비율 90% 이상을 목표로 실기기 표본을 수집

숫자는 아직 출시 확정값이 아니다. iPhone 기종·조도·거리별 측정 후 확정한다.

## 8. 승인 요청 범위

승인 후에는 다음 순서로 작은 변경 단위로 구현한다.

1. 품질 지표와 화면 상태를 추가하되, 기존 규칙 결과는 바꾸지 않는 진단 단계
2. quality gate로 불안정 frame의 Warning/rep 확정만 보류
3. 핵심 관절의 적응형 안정화와 body-scale jump 기준
4. 1~2초 캘리브레이션 및 profile 자동 하향
5. iPhone 60초/10분 검증 결과를 문서에 기록

각 단계에서 Unity 결정론 QA와 실기기 테스트를 실행하고, 안정화 지연·정확 반복 수·발열이 나빠지면 해당 단계만 되돌릴 수 있게 분리한다.

## 9. 2026-07-23 1차 구현 결과

반영 완료:

- raw landmark 기반 `Good` / `Degraded` / `Unavailable` 품질 평가
- 안정적인 프레임 3개 이후 분석 시작, 낮은 신뢰도 3프레임 지속 시 Unavailable 전환
- 전신 크기, 화면 잘림, hip/shoulder 가로 폭을 이용한 전면 촬영 품질 검사
- Good이 아닌 동안 phase·자세 Warning·정확 반복 확정을 보류하고 현재 rep 증거 초기화
- 추적 중단 뒤에는 서 있는 준비 자세가 다시 확인되어야 rep 판정을 재개해, 중간 하강·상승만으로 부분 rep가 만들어지는 문제 방지
- 낮은 confidence 좌표를 잠깐 유지하더라도 현재 낮은 score를 보존해 분석 관절로 오인하지 않도록 수정
- torso 길이에 비례한 jump 임계값과 동작 속도·confidence 기반 적응형 EMA 적용
- 빠른 동작에서는 3-샘플 median과 최신 raw를 혼합해 smoothing 지연 완화
- 큰 이동이 지속될 때 한 프레임 snap 대신 빠른 보간으로 재획득
- 화면 좌표의 직립 기준축을 반대로 사용해 정상 상체를 약 180°로 계산하던 오류 수정 (`Vector2.up` → `Vector2.down`)
- 모바일 상태 문구와 디버그 상태 패널에 추적 품질/사용자 안내 표시
- 정상 전면 자세, 발목 잘림, 지속 저신뢰, held-low-confidence에 대한 결정론 QA 추가

실기기 측정 후 확정할 항목:

- `minimumTrackedBodyHeight`, `minimumFrontalBodySpan`의 iPhone 기종별 체감값
- stationary/moving smoothing alpha와 body-scale jump 배수
- Good/Unavailable 전환에 필요한 연속 프레임 수
- 자동 12→10→8 FPS 하향 정책과 1~2초 시작 캘리브레이션

마지막 두 항목은 현재 코드에 자동 적용하지 않았다. 실제 iPhone p95와 저신뢰 비율 없이 자동 FPS/캘리브레이션을 켜면 기기별로 오히려 판정 지연이 커질 수 있으므로, 이번 1차 구현에서 수집 가능한 상태값을 먼저 검증한다.
