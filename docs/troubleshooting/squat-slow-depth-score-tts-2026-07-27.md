# 느린 스쿼트 깊이 판정·정확 점수·TTS 중복 오류

작성일: 2026-07-27
대상: 전면 카메라 실시간 스쿼트 판정

## 보고된 증상

1. 빠른 스쿼트는 정상 판정되지만 천천히 내려가면 최저점과 반복 판정이 부정확했다.
2. 최저점에서 “조금 더 내려가세요” 안내를 받은 뒤 실제로 더 내려가도 정확 자세 점수가 증가하지 않았다.
3. 같은 깊이 안내가 앉은 상태와 일어서는 시점에 두 번 들렸다.
4. “괜찮습니다”라는 문구와 실제 횟수 미인정 조건이 서로 모순되어 사용자가 현재 판정을 오해할 수 있었다.
5. 전면 카메라 2D 화면에서 고관절과 무릎 높이가 거의 같아도 정확히 `0`을 넘지 못하면 깊이 미달이 반복됐다.
6. 사용자가 가만히 서 있는 `Standing` 상태에서도 일반 자세 교정 TTS 후보가 발생할 수 있었다.
7. 느린 스쿼트에서 전체 반복은 증가하지만, 동작 중 잠깐 검출된 경고가 남아 정확 자세 카운트가 증가하지 않는 경우가 있었다.
8. 설정 목표를 달성해도 세션이 자동 종료되지 않았고 휴식, 칼로리, 점수, 자세 문제 요약 화면이 없었다.
9. `2회 × 2세트`처럼 설정해도 2회 뒤에 쉬지 않고 전체 4회를 마친 다음에만 휴식이 시작됐다.

## 원인

### 1. 느린 방향 변화가 phase 임계값 아래에 머묾

기존 phase 검출은 무릎 각속도 `12°/s`, 골반 이동 속도 `0.08/s`를 기준으로 하강·상승 방향을 결정했다. 천천히 움직이면 실제로 계속 내려가는 중이어도 이 임계값을 넘지 못해 `Descent` 증거가 부족해지거나, 고정 Bottom 각도에 오래 머문 것만으로 너무 일찍 `Bottom`이 될 수 있었다.

### 2. 교정 완료 전의 임시 깊이 경고가 반복 전체 오류로 남음

`squat_depth_shallow` 경고는 사용자가 같은 반복 안에서 더 내려가 깊이 조건을 통과해도 `RepQualityAccumulator`에 이미 누적되어 있었다. 반복 횟수 자체는 깊이 조건을 통과해야 증가하지만, 정확 자세 점수는 이전의 임시 경고 때문에 실패할 수 있었다.

### 3. TTS 제한이 시간 기준일 뿐 반복 기준은 아니었음

최저점에 오래 머물면 중복 제한 시간이 지난 후 같은 경고가 다시 발행될 수 있었다. 또한 다른 음성이 재생 중이면 깊이 안내가 TTS 대기 슬롯에 남아, 사용자가 자세를 교정했거나 이미 일어선 뒤 재생될 수 있었다.

### 4. RAG 문구와 판정 심각도가 불일치

깊이 미달은 횟수를 막는 `Warning`인데 RAG 실시간 문구와 JSON 심각도는 “괜찮습니다. 가능하면…”이라는 선택적 `Info` 표현을 사용했다.

### 5. 단일 2D 경계값이 카메라 투영 오차를 흡수하지 못함

기존 `hipToKneeDepth >= 0`은 고관절 중심이 무릎 중심과 정확히 같은 높이여야 했다. 랜드마크 흔들림, 카메라 각도, 전면 투영 때문에 육안상 같은 높이도 작은 음수로 측정될 수 있었다. 반대로 단순 허용값만 추가하면 우연히 높이만 맞은 얕은 자세가 통과할 위험이 있었다.

### 6. Standing phase에 대한 최종 음성 출력 게이트가 없음

일부 자세 규칙은 phase 제한 없이 후보를 만들었고, 대기 TTS가 있으면 사용자가 동작을 끝내고 서 있는 동안 재생될 수 있었다.

### 7. 단일 고지속 경고를 즉시 확정 오류로 고정

자세 규칙의 `PersistenceRatio`는 최근 분석 창을 바탕으로 한다. 느리게 움직일수록 과거 프레임이 포함된 고지속 경고가 한 번 나타날 가능성이 커지는데, 기존 `RepQualityAccumulator`는 그 한 번만으로 `HasPersistentWarning`을 세션 반복 끝까지 고정했다. 사용자가 같은 반복 안에서 자세를 고쳐도 해제되지 않아 전체 반복만 오르고 정확 자세 카운트는 멈출 수 있었다.

깊이 판정과 정확 자세 판정은 서로 다른 단계다. 전체 반복 증가는 깊이와 phase 완료를 뜻하고, 정확 자세 카운트는 무릎 정렬·상체·골반·균형 등 반복 품질까지 통과해야 증가한다. 따라서 실제 오류가 있다면 두 값이 달라지는 것은 정상이나, 교정된 일시 경고 때문에 달라지는 것은 정상 흐름이 아니다.

## 해결 내용

### 느린 스쿼트 phase 추적

- 기존 노이즈 억제 임계값은 유지하고, 실제 방향 추적에는 그 값의 15%와 최소 방향 속도를 적용했다.
- 천천히 계속 내려가는 동안은 `Descent`를 유지한다.
- Bottom 구간에서 사용자가 안내를 듣고 다시 내려가면 `Descent`로 복귀한다.
- Bottom dwell은 하강이 멈춘 근거가 있을 때만 인정한다.

### 교정 후 정확 점수 반영

- `squat_depth_shallow`를 현재 반복에서 교정 가능한 임시 안내로 취급한다.
- 해당 안내를 받았더라도 같은 반복에서 엉덩이–무릎 깊이 하한선을 통과하면 정확 자세 품질을 막지 않는다.
- 1차 높이 판정은 신체 크기 대비 `0.03`의 2D 투영 허용 범위를 적용하고 연속 2개 신뢰 프레임을 요구한다.
- 2차 판정은 최소 무릎각 `135°` 이하 또는 서기 대비 골반 하강량 `0.08` 이상을 요구한다. 1차 높이만 우연히 맞는 자세는 횟수로 인정하지 않는다.
- 무릎 정렬, 균형, 상체 기울기 등 실제 자세 오류는 이전과 동일하게 정확 점수를 막는다.
- 한 번 관찰된 고지속 경고는 확정 감점으로 고정하지 않는다.
- 같은 `RuleId`의 오류가 최소 2개 프레임 이상 관찰되고, 해당 반복 유효 프레임의 35% 이상일 때만 일반 자세 오류를 확정한다. 서로 다른 일시 경고를 합쳐 하나의 오류로 만들지 않는다.
- Critical 오류는 같은 규칙이 설정된 최소 Critical 프레임 수 이상 반복되면 별도로 확정한다.
- 정확 카운트가 오르지 않은 완료 반복은 확정된 `RuleId`를 세션 문제 횟수에 기록하여 결과 화면에서 원인을 확인할 수 있게 했다.

### 고관절–무릎 1차 조건의 의미

- 화면 좌표의 y축은 아래로 증가하므로 코드의 1차 조건은 정규화한 `hipY - kneeY >= -0.03`이다. 의미상 “고관절 높이가 무릎과 같거나 약간 위의 투영 허용 범위 안”인지 확인한다.
- 고관절이 무릎의 앞/뒤에 보이는 x축 또는 카메라 깊이 z축만으로 정확한 스쿼트를 확정하지 않는다. 카메라 투영, 촬영 방향, 신체 비율에 따라 앞뒤 관계가 달라 보일 수 있기 때문이다.
- 1차 높이를 통과한 뒤 `무릎각 <= 135°` 또는 `서기 대비 골반 하강량 >= 0.08`을 2차 증거로 사용한다.
- 그 뒤 반복 전체의 자세 오류를 검사해 정확 자세 카운트를 결정한다.

### TTS 중복 및 지연 재생 차단

- `HasIssuedShallowDepthFeedbackInCurrentRep` latch를 추가해 반복당 깊이 안내를 최대 한 번만 발행한다.
- 깊이를 통과하거나 Bottom을 벗어나거나 추적이 중단·초기화되면 아직 플랫폼 TTS에 전달되지 않은 `squat_depth_shallow` 요청을 취소한다.
- 일반 자세 교정 TTS는 `Descent`, `Bottom`, `Ascent`에서만 허용하고 `Standing`/`Unknown`에서는 새로 발생시키지 않는다.
- Standing 진입 시 대기 중인 `squat_*` 자세 안내를 취소하되, 방금 완료한 `정확합니다. N개` 횟수 안내는 유지한다.
- 이미 재생을 시작한 음성은 강제로 잘라 문장을 훼손하지 않고, 대기 중인 오래된 안내만 제거한다.
- 안내 문구를 “조금 더 깊게 내려간 뒤 최저점에서 잠시 유지해 주세요.”로 통일하고 JSON 심각도를 `Warning`으로 맞췄다.

### 세트 휴식·목표 완료·결과 화면

- 목표 화면에 `세트 간 휴식(초)` 설정을 추가했고 테스트 기본값을 3초로 지정했다.
- `CorrectRepCount`가 `반복 횟수`의 배수에 도달하고 마지막 세트가 아니면 추적과 TTS를 일시 종료하고 세트 휴식 화면으로 전환한다.
- 휴식 화면은 완료 세트와 다음 세트, 남은 초를 표시한다. 시간이 끝나면 카메라 추적을 다시 시작하며 `다음 세트 바로 시작`으로 건너뛸 수 있다.
- 세트 휴식 중 `ExercisePhaseDetector`가 초기화되더라도 세션 전체 시도 횟수는 `TotalRepCount`에 별도로 누적해 정확 횟수, 자세 문제, 운동 시간과 함께 보존한다. 휴식 시간은 운동 시간에서 제외한다.
- 마지막 정확 자세 목표에 도달하면 추가 세트 휴식 없이 추적을 종료하고 결과 화면으로 이동한다.
- 예: `2회 × 2세트`, 휴식 3초는 `2회 → 3초 휴식 → 2회 → 종료/결과` 순서다.
- 결과 화면은 전체 반복, 정확 반복, 운동 시간, 예상 칼로리, 운동 점수와 최대 3개의 주요 자세 문제를 표시한다.
- 칼로리는 현재 운동별 `kcal/회 × 전체 반복 수` 추정치다.
- 운동 점수는 `정확 반복 / 전체 반복 × 100`을 반올림한 값이다.
- 결제 계층이 `SetPaidStretchingAccess(true)`를 호출하면 `ExpertContent` 권한이 열리고, 가장 많이 기록된 자세 문제에 맞춘 회복 스트레칭을 결과 화면에 표시한다. 미결제 사용자는 잠금 안내만 본다.

## 자동 검증

`HealthcareQaSuite`에 다음 회귀 시나리오를 추가했다.

- 저속 무릎 각속도(`-5°/s`) 하강도 `Descent → Bottom → Ascent → Standing`으로 1회 판정
- 하강 중에는 Bottom이 조기에 확정되지 않음
- 같은 반복에서 깊이 안내가 한 번만 생성됨
- 깊이 안내 후 같은 반복에서 교정하면 정확 자세 점수가 유지됨
- 교정 완료 후 대기 중인 깊이 TTS가 플랫폼 backend에 진입하지 않음
- 고관절이 무릎보다 `-0.015`만큼 위로 측정된 near-level 자세도 2차 깊이가 맞으면 인정
- 1차 높이만 통과하고 2차 깊이가 부족한 자세 및 `-0.04`로 명확히 높은 자세는 거부
- Standing/Unknown 일반 자세 TTS 차단 및 대기 `squat_*` 취소
- 단 한 번의 오래된 고지속 경고는 정확 점수를 막지 않음
- 동일 자세 오류가 반복 프레임 비율을 충족하면 정확 점수를 막고 해당 `RuleId`가 결과 리포트용으로 보존됨
- 결과 점수가 `정확/전체 × 100`으로 계산되고 0회에서 안전하게 0점 처리됨
- `2회 × 2세트`에서 정확 2회째 한 번만 쉬고 최종 4회째에는 세트 휴식을 시작하지 않음
- 세트 간 휴식 기본값 3초 및 결제 시스템 연결용 공개 권한 메서드 존재
- 기존 빠른 스쿼트, 적응형 깊이, 안전 하한선, TTS 우선순위 테스트 회귀 없음

## 실기기 확인 항목

1. 3~5초 동안 천천히 내려가는 스쿼트를 5회 수행해 전체/정확 횟수가 각각 5회 증가하는지 확인한다.
2. 얕은 최저점에서 안내를 한 번 들은 뒤 같은 반복에서 더 내려가 정확 점수가 증가하는지 확인한다.
3. 얕은 최저점을 3초 이상 유지해도 같은 문장이 두 번 나오지 않는지 확인한다.
4. 다른 TTS가 재생 중인 상태에서 자세를 교정하고 일어났을 때 오래된 깊이 안내가 뒤늦게 나오지 않는지 확인한다.
5. 가만히 서 있는 동안 일반 자세 교정 TTS가 새로 나오지 않는지 확인한다.
6. `2회 × 2세트`에서 정확 2회 후 3초 쉬고 자동으로 다음 세트를 시작하며, 정확 4회 후에는 바로 종료 결과로 이동하는지 확인한다.
7. 일부 잘못된 반복을 섞었을 때 결과의 전체/정확 횟수와 운동 점수가 일치하는지 확인한다.
8. 결과 화면에 실제 확정 자세 문제와 횟수가 나오고, 결제 권한 ON/OFF에 따라 스트레칭 추천이 잠금/표시되는지 확인한다.
