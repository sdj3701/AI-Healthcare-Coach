# 스쿼트 깊이 실패 원인별 TTS 분리 계획

## 목표

- 스쿼트 최저점에서 깊이 판정이 실패했을 때 사용자가 실패 원인을 즉시 구분할 수 있도록 TTS 문구를 1차 높이 조건과 2차 깊이 조건으로 분리한다.
- 정상적인 방향 전환 스쿼트에 불필요하게 “최저점에서 멈추라”는 인상을 주는 문구를 제거한다.

## 변경 범위

- `RealtimePoseRuleEngine`의 `squat_depth_shallow` 안내 생성부에서 실패 단계를 판별한다.
- 1차 실패 시 다음 의미의 안내를 출력한다.
  - 엉덩이와 무릎 높이가 아직 충분히 가까워지지 않았으므로 엉덩이를 더 내려야 한다.
- 1차 통과 후 2차 실패 시 다음 의미의 안내를 출력한다.
  - 무릎 각도와 골반 하강량이 모두 2차 깊이 기준을 통과하지 못했으므로 조금 더 깊게 내려야 한다.
- RAG 지식 파일의 공통 문구가 단계별 런타임 안내를 덮어쓰지 않는지 확인하고, 필요하면 원인별 런타임 문구를 보존하도록 조정한다.
- 반복당 깊이 안내 1회, 교정 완료 시 대기 TTS 취소, Standing 진입 시 자세 TTS 취소 정책은 유지한다.

## 제안 TTS

1. 1차 높이 조건 실패
   - `엉덩이와 무릎 높이가 아직 충분히 가까워지지 않았습니다. 엉덩이를 조금 더 내려 주세요.`
2. 2차 깊이 조건 실패
   - `무릎 굽힘과 골반 하강량이 아직 부족합니다. 조금 더 깊게 내려 주세요.`

## 검증

- [x] 1차 높이 조건 실패 이벤트가 1차 전용 문구를 생성한다.
- [x] 1차 통과·2차 실패 이벤트가 2차 전용 문구를 생성한다.
- [x] 두 단계 통과 후에는 `squat_depth_shallow` TTS가 생성되지 않는다.
- [x] 기존 반복당 1회 제한과 대기 TTS 취소 동작이 유지된다.
- [x] Unity 컴파일 및 Healthcare QA Suite를 실행해 회귀 오류가 없는지 확인한다.

## 완료 결과

- `FeedbackEvent.PreferTemplateText`를 추가해 원인별 깊이 안내가 공통 RAG 문구로 대체되지 않고 TTS까지 전달되도록 했다.
- 1차 높이 실패와 2차 깊이 실패에 서로 다른 문구를 적용했다.
- Unity `6000.3.18f1` 임시 프로젝트 복사본에서 `Rag.Healthcare.Editor.HealthcareQaSuite.RunBatch`를 실행했고 `AI_HEALTHCARE_QA_PASSED`를 확인했다.
